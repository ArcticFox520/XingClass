# 技术决策记录（ADR）

> 记录“为什么这样做”。如果实现与本文冲突，以 AGENT_GUIDE.md 为准，并更新本文。

## D-001 手动依赖注入，不引入 Hilt

**背景**：整个依赖图不足 10 个对象（OkHttp、Api、CookieJar、两个 Repository、存储、时钟）。
**决策**：`AppContainer` 手动构造；ViewModel 通过 `viewModelFactory { initializer { … } }` 获取依赖。
**理由**：无 KSP/注解处理、构建更快、依赖关系一眼可见，符合“每个库都要有理由”。
**代价**：对象增多后需要手动维护；当前规模可接受。

## D-002 课表缓存使用 JSON 文件，不使用 Room

**背景**：只有一个学生、一份课表，字段结构稳定，数据量 < 100 条。
**决策**：`filesDir/course-cache.json`，临时文件 + rename 原子写，损坏即丢弃。
v3 起保存 `week / realCurrentWeek / maxWeek / lessonTimes`，保证离线时仍能显示
“上次查看的周”及节次时间。
**理由**：避免 Room + KSP 的构建开销和新依赖；读取失败可安全降级为 cache miss。
**代价**：没有查询能力；课程表不需要。若未来加入多学期/多账号，再迁移到 Room。

## D-003 使用 androidx.security:security-crypto

**背景**：账号提示与 Cookie 必须加密落盘，且应使用 Android Keystore。
**决策**：`EncryptedSharedPreferences`（MasterKey AES-256-GCM，键 AES-SIV，值 AES-GCM）。
**理由**：Tink 支撑的成熟实现，避免自研密码学；比手写 Keystore AES/GCM + IV 管理更不容易出错。
**代价**：该库处于维护模式（1.1.0-alpha）。已在 `KeystoreSecureStorage` 中封装，
未来替换只影响一个类。失败时退化为进程内存储，绝不降级明文。

## D-004 永不持久化密码

**背景**：指南要求“读取本地凭据 → 检查本地 Session”。
**决策**：只持久化账号提示和 Cookie；密码仅在登录请求期间存在，成功即从 state 清空。
**理由**：密码是长期凭据，泄露代价远高于一次会话；有 Cookie 就能自动保持登录。
**代价**：Session 失效后需要用户重新输入密码——这正是指南要求的“提示重新登录”。

## D-005 容错解析 + 真实结构优先

**背景**：开发初期 `getMyLessons` 的完整响应结构未知，抓包只给了部分字段。
**决策**：先按多个容器键/字段别名做容错；2026-11-06 用测试账号完成真实联调后，
以真实结构为准（`data.lessonArray`、`dayOfWeek`、`beginNumber`、`length`），同时保留别名兜底。
找不到关键字段的条目直接丢弃，不猜测。
**理由**：不能因为字段未知就让整个课表不可用，也不能把猜测写成事实；真实结构应固化进测试。
**代价**：真实联调当场暴露了两个问题并已修复：
1. `data.schools` 是空数组，旧兜底逻辑会把它当成“空课表”，导致 0 门课；
2. `courseId` 是课程级 ID（同一门课一周出现多次），旧逻辑用它去重，14 条只剩 10 条。
现在 `lessonArray` 是首选容器，兜底只接受“非空且像课程”的数组；实例 ID 使用唯一 `lessonId`。

## D-006 鉴权状态采用 VALID / INVALID / UNKNOWN 三态

**背景**：资料只记录了 `getauthstatus/v2` 的“参数为空”失败响应，无法证明这代表 Cookie 失效。
**验证**：2026-11-06 真实联调确认——**即使刚登录成功、Cookie 完全有效**，该接口仍然返回
`{"mes":"参数为空","type":"1","status":false}`。它不能用于正向确认会话。
**决策**：只有明确失效语义才 `INVALID`；断网、无法解析、“参数为空”一律 `UNKNOWN`，继续进入课表。
**理由**：避免每次启动/断网都被强制登出；课程请求仍能最终判定会话。
**代价**：失效 Cookie 可能多存活一次课程请求的时间；该请求会触发清理。

## D-007 自动主题每分钟检查

**背景**：需求为 08:00–22:00 白天。
**决策**：RootViewModel 每 60 秒根据当前小时重算明暗，仅 AUTO 模式生效。
**理由**：分钟级足够，避免每秒重组整个界面。
**代价**：跨过 08:00/22:00 后最多延迟 1 分钟切换。

## D-008 主课表用自定义 Layout，不用 Lazy/Scroll

**背景**：必须一屏、10 节均分、7 天、跨节。
**决策**：固定 7×10 网格，自定义 `Layout` 按 day/start/span 测量并放置；网格底座外凸内凹由
`NeumorphicSurface` 绘制。
**理由**：满足“禁止 LazyColumn/LazyRow/verticalScroll/horizontalScroll”的硬性要求；
约束固定时性能稳定，不需要 ConstraintLayout 依赖。
**代价**：需要自己处理边界取整与重叠分列（已单测）。

## D-009 课程颜色由标题哈希决定

**背景**：超星响应未提供可用的颜色字段。
**决策**：用稳定字符哈希映射到 8 个低饱和色板。
**理由**：同一门课跨刷新/跨设备颜色一致；无需额外存储。
**代价**：不同课程可能撞色；8 色对一周课表足够。

## D-010 课程卡文字行数按测量高度计算

**背景**：7 列网格中卡片宽度仅约 40dp，不同屏幕高度差异大。
**决策**：课程卡使用 `BoxWithConstraints`，按实际高度推导标题行数与是否显示地点。
**理由**：防止超长课程名撑破网格或突然截断。
**代价**：每张卡多一次约束读取；静态课表开销可忽略。

## D-011 显示每节课的上课/下课时间

**背景**：开发初期资料没有可信的节次时间表；后续真实响应中
`curriculum.lessonTimeConfigArray` 提供了 `["08:30-09:15", "09:20-10:05", …]`。
**决策（已被用户明确要求覆盖）**：
- 左侧节数栏：节数下方显示该节的上课/下课时间（空间不足时隐藏时间，只留节数）；
- 课程抽屉：左侧时间列显示整段课程的**上课时间与下课时间**，不再显示“1-2 节”；
- 时间随课表缓存（v3）一起保存，离线可用。
**理由**：用户需要直接看到上下课时间；数据来自真实响应，无需编造。
**代价**：左栏信息密度增加，极小屏/超大字号时可能只显示节数。

## D-012 单 Activity + 状态机导航，不引入 Navigation Compose

**背景**：只有登录、课表、设置、抽屉四个目的地，无深链接需求。
**决策**：`RootDestination` 枚举 + `sessionKey` 驱动的 ViewModel 隔离。
**理由**：少一个依赖；返回逻辑明确；登出后通过 key 强制重建课表 ViewModel，避免残留旧账号数据。
**代价**：不支持系统返回栈的复杂场景；MVP 无此需求。

## D-013 Material3 只用于文本/图标语义，不用于可见表面

**背景**：新拟物要求自定义双阴影、无 Material elevation。
**决策**：所有可见容器由 `NeumorphicSurface` 自绘；Material3 仅提供 `Text`、`Icon`、
`LocalContentColor` 与主题色语义。
**理由**：避免 Material 默认阴影/涟漪破坏光影规则；同时保留可访问性与文本排版能力。

## D-014 按压效果用阴影状态插值，不使用位移

**背景**：新拟物规范明确禁止 translate。
**决策**：`pressProgress` 在 Raised 阴影淡出与 Inset 阴影淡入之间插值，300ms。
**理由**：符合“外凸变内凹”且布局稳定。
**代价**：绘制两次阴影；静态界面开销可接受。

## D-015 空但成功的响应会覆盖缓存

**背景**：服务器可能合法返回“本学期没有课”。
**决策**：只有成功解析出课程容器（可为空数组）时才写缓存；解析失败/网络失败不写。
**理由**：避免把解析失败误当成“没有课”而清空可用课表。
**代价**：真正的空课表会覆盖旧缓存，这是正确行为。

## D-016 APK 命名与 arm64 限制

**背景**：指南要求 Release APK 名为 `XingClass-arm64-v8a-release.apk`，且只支持 arm64-v8a。
**决策**：`abiFilters += "arm64-v8a"`，`androidComponents.onVariants` 统一命名；CI 校验无其他 ABI 原生库。
**理由**：当前无原生代码，命名与 ABI 过滤是防止未来回归的护栏。
**代价**：若未来加入只提供 x86 的原生依赖，构建会失败——这是期望的。

## D-017 Release 无签名时回退 debug 签名

**背景**：仓库不能提交 keystore，CI fork 也可能没有 Secrets。
**决策**：有完整签名配置则使用 release key，否则用 debug key 保证产物可安装；workflow 明确警告。
**理由**：保证 `assembleRelease` 在任何环境都能产出可验证的 APK，同时不伪造“正式签名”。
**代价**：未配置 Secrets 的产物不能正式分发；文档已写明。

## D-018 实网集成测试默认跳过，凭据只走环境变量

**背景**：接口结构必须用真实账号验证，但 CI 与仓库绝不能持有凭据。
**决策**：`LiveChaoxingApiTest` 使用 `XINGCLASS_TEST_ACCOUNT` / `XINGCLASS_TEST_PASSWORD` 环境变量，
缺失时通过 `Assume.assumeTrue` 跳过；测试不打印账号、密码、Cookie、响应体或课程名。
提交到仓库的响应样本已脱敏。
**理由**：既能复现实网验证，又不会把凭据与个人课表带入版本库或 CI 日志。
**代价**：CI 中该测试显示为 skipped；需要人工在有凭据的环境执行一次。

## D-019 Course ID 使用“上课实例”粒度

**背景**：真实响应中 `lessonId` 唯一，`courseId` 是课程级 ID，同一门课一周内会重复出现。
**决策**：内部 `Course.id = <lessonId|cx>@<day>-<start>-<span>-<titleHash>`，
去重只删除真正相同的实例。
**理由**：Compose 的 key 与本地缓存都要求唯一；否则同一门课的多次上课会互相覆盖/被误删。
**代价**：ID 不是原始 `lessonId`，但不对外展示，也不参与网络请求。

## D-020 周次切换使用 `week` 参数

**背景**：用户要求增加周次切换；原文档只记录了 `curTime` 参数。
**验证（2026-11-06）**：
- `curTime` 传第 9 周、第 11 周、now±7 天，返回的仍是真实本周（第 10 周）；
- 真正的参数是 `week`：`week=9` → 16 条、日期 10-26..11-01、`weeks="9"`；
  `week=11` → 14 条、日期 11-09..11-14；`week=1/2/22` → 空数组；越界 0/23/999 仍是 200 + 空；
- 无论 `week` 是多少，响应里的 `currentWeek` / `realCurrentWeek` 始终是真实本周。

**决策**：API 增加 `week` 参数；客户端自行维护“选中周”，响应的 `currentWeek` 只作为
“真实本周”；缓存保存三者；切换失败保留当前周与课表，仅提示失败。
**理由**：不能在客户端把响应当成“选中周”，否则“回到本周”和周标签都会错。
**代价**：多维护三个周次字段；切换需要一次网络请求。

## D-021 加强新拟物凹凸感

**背景**：用户反馈视觉凹凸感不够强。
**决策**：阴影档位提升为 SMALL 4/9/4、MEDIUM 7/14/7、LARGE 10/22/10（offset/blur/depth，dp）；
浅色暗阴影 `#A6ADB8`，深色亮/暗阴影 `#434D5A`/`#15191F`；网格内边距 8dp、抽屉槽 10dp。
**理由**：提高明暗对比，同时保持“左上亮、右下暗”的固定光源；增加内边距避免小卡片的强阴影
被网格裁切或互相糊住。
**代价**：小尺寸组件（日期 Tab、节数块）阴影更明显，视觉更“重”。

## D-022 课程卡按实测空间排版；卡片分行、抽屉单行

**背景**：用户反馈卡片有空余但课程名/地点被隐藏；随后要求抽屉中的楼栋、教室与教师
**不要分行**（例如“示例楼 · C201 · 王老师”）。
**决策**：
- `CourseCardLayout` 以可用高度、真实行高（含 fontScale）计算标题行数（1..5）与地点行数（0..2）；
- 移除“跨节数 ≥ 2 才显示地点”的固定门槛；
- **网格卡片**空间足够时楼栋、教室分两行，空间不足时回退完整地点一行；
- **抽屉**改为标题一行 + “楼栋 · 教室 · 教师”单行，左侧时间列显示起止时间；
- 抽屉外壳无阴影，内部 LARGE 凹槽（12dp 内边距），课程卡从凹槽外凸。
**理由**：网格卡片空间最紧张，需要分行提高可读性；抽屉横向空间充足，单行更紧凑。
**代价**：抽屉的元信息在极窄屏幕上可能被省略号截断。

## D-023 诊断日志与导出

**背景**：用户要求日志记录与导出、课程响应数据导出。
**决策**：
- `DiagnosticsLog` 持久化到 `filesDir/logs/diagnostics.log`（256KB 上限，内存 500 条兜底）；
  `AndroidLogger` 只写入固定事件名、异常类名以及安全的周次/数量；
- 设置页“诊断”提供“导出运行日志”（txt）与“导出课程数据”（json）；
- 导出文件写入 cache，通过 FileProvider + 系统分享面板交给用户；
- 课程导出是解析后的课表数据（周次、节次时间、课程/地点/教师/颜色），**不保留原始 HTTP body**。
**理由**：满足排错与数据导出需求，同时不把账号、密码、Cookie、Token 或响应体写入日志。
**代价**：日志不能用于复现服务端原始响应；需要时另加显式调试开关。

## D-024 相同且时间连贯的课程合并

**背景**：用户要求“完全相同并且时间连贯的课程展示成单个方块”。
**决策**：
- `CourseMerger` 在数据层（remote→snapshot 之前）合并同一天、同标题/地点/教师、
  且节次相邻、实际时间间隔 ≤30 分钟的课程；
- 重叠的相同条目直接合并；跨午休（120 分钟）或晚休（60 分钟）不合并；
- 合并后 `span` 取并集，`id` 由源 id 组合，抽屉与课表均显示单个方块。
**理由**：避免同一门连堂课被拆成多个卡片，同时不把上午/下午的同一门课错误合并。
**代价**：合并后的 id 是组合 id；合并逻辑依赖真实节次时间，缺失时退化为“相邻节次即合并”。

## D-025 界面文案最小化

**背景**：用户要求删除大部分解释说明性提示。
**决策**：移除登录隐私说明、主题自动切换说明、账号加密说明、缓存说明、关于页免责说明，
以及空课表/空抽屉的操作提示；只保留状态、错误、确认与操作标签。
**理由**：界面更简洁；关键操作本身已能表达含义。
**代价**：新用户对隐私/缓存策略的了解需要查阅文档而非 UI。
